# i18n work: $ARGUMENTS

Translations are already in `public.translations` (8 languages: en, fr, nl,
de, es, it, pt, zh). The job is to **plumb them through** without
hardcoding strings in components.

## Schema (existing)

```
translations
  language      text  (e.g. 'en', 'fr')
  entity_type   text  (e.g. 'destination', 'category', 'ui')
  entity_id     uuid  (FK to the entity, nullable for ui strings)
  field         text  (e.g. 'name', 'description')
  value         text
  is_verified   boolean
  translated_by text
```

## Pattern: translated entity reads

```ts
// lib/i18n/translations.ts (server)
export async function withTranslations<T extends { id: string }>(
  rows: T[],
  entityType: string,
  language: string,
): Promise<Array<T & { _t: Record<string, string> }>> {
  if (!rows.length) return rows.map((r) => ({ ...r, _t: {} }));
  const supabase = createClient();
  const { data } = await supabase
    .from("translations")
    .select("entity_id, field, value")
    .eq("entity_type", entityType)
    .eq("language", language)
    .in("entity_id", rows.map((r) => r.id));
  const byId = new Map<string, Record<string, string>>();
  (data ?? []).forEach((t) => {
    if (!byId.has(t.entity_id)) byId.set(t.entity_id, {});
    byId.get(t.entity_id)![t.field] = t.value;
  });
  return rows.map((r) => ({ ...r, _t: byId.get(r.id) ?? {} }));
}
```

Use as: `const t = stop._t.name ?? stop.name`.

## Pattern: language detection

- Signed-in users: `users.preferred_language` (we already collect it)
- Anonymous: `Accept-Language` header → fallback to `en`

## Admin UI

When editing a destination, show a "Translations" tab with one row per
supported language and the editable fields. Save via a server action
that upserts into `translations`.

## Public UI

- Add a language switcher in the header (later)
- Persist choice in a cookie + sync to user profile if signed in

## Hard rules

- Never inline English strings that are user-facing inside components.
  Pull them from a `messages.en.ts` (or eventually the `translations` table
  with `entity_type='ui'`).
- All currency / dates use `Intl` formatters with the user's language.
- Never machine-translate critical content (booking T&Cs, refund policy)
  without human review.
